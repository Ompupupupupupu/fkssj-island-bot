# 脚本清单（权威参考）

> **职责**：本 skill 全部脚本的角色、参数、exit code 权威表，以及 RESULT 行位置、
> 路径书写两个已知坑。
> **何时读取**：需要某个脚本的参数、exit code、行为细节时。

| 文件 | 角色 | 参数 | exit code |
|---|---|---|---|
| `scripts/game_lib.py` | 共享库（常量+判定函数），被各脚本导入，不直接运行 | - | - |
| `scripts/pyadb.py` | adb 直连库，被 game_lib 导入，不直接运行 | - | - |
| `scripts/setup_emulator.py` | 检查并修正雷电模拟器基础配置：要求平板版配置分辨率 1920×1080、DPI 280；不符时自动改写实例配置；模拟器运行中修正后需重启生效（重启后重跑验证，仍不符则关模拟器再跑本脚本修正后启动）；安装目录自动探测，未命中需显式指定 | 可选 `--ld-dir <雷电安装目录>`、`--instance <实例目录名，默认 leidian0>` | 0=符合或已修正(模拟器未运行)；1=读写失败或安装目录未找到；2=已修正需重启模拟器 |
| `scripts/start_game.py` | 启动游戏：已运行则报告状态不重启；未运行则冷启动+轮询等主界面（上限 60 秒），超时走 check_main 兜底 | 无 | 0=游戏运行中；1=启动失败 |
| `scripts/stop_game.py` | 停止游戏：force-stop 后 2 秒复检，仍在则重试一次 | 无 | 0=已停止（含本来就未运行）；1=停止失败 |
| `scripts/game_status.py` | 只读探测游戏/模拟器状态（不截图不点按，只依赖 pyadb，供定时任务执行前探测）：区分"模拟器未启动 / 模拟器已启动 游戏未运行 / 游戏运行中" | 无 | 0=游戏运行中；2=需用户行动（模拟器未启动或游戏未运行）；1=检测异常 |
| `scripts/check_main.py` | 检查是否在主界面；不在则自动恢复：第 1 次按界面类型点按钮（城战→"基地"，其他→返回），第 2 次非城战点兜底按钮（城战仍点"基地"），之后 2 次复检（每次等 3 秒）未回主界面按界面类型层层退回，全部尝试后等 3 秒终检（最后一次点击生效不算失败） | 无 | 0=已在/已回主界面；1=恢复失败 |
| `scripts/check_ships.py` | 三艘贸易船状态检查 + 自动收货交货 + 博物馆收益领取（人气币、寻宝小队奖励，贸易处理完回主界面后进博物馆，展厅视角先移到最左再检测）：船未回来→跳过；已回来→收货→结算→交货，交货后 0.5s 检测"所需产品不足"弹窗（缺货交货被拒会被弹窗挡屏）：命中→点弹窗退出键回贸易页再复检；未命中=交货成功后复检；博物馆部分：人气币气泡有则领取，随后必进寻宝界面数完成小队数（无论有无完成，0 支也进）并逐队收奖；有可派小队则上下视角逐区扫描筛出可寻宝区域，从队首区域起逐区派遣（进派遣界面选人确认后逐槽位试派出，不可派区域两连退回寻宝界面）直至小队派完或区域用尽，再回主界面。RESULT 含 寻宝奖励/派出 字段。不在主界面时自动调 check_main.py 恢复后继续 | 无 | 0=处理完；1=主界面恢复失败或未知状态；2=有船货物不足（需用户补货） |
| `scripts/check_res.py` | 7 种资源剩余数量 + 上限 OCR（只读，不采集），低于上限 70% 标记不足。不在主界面时自动调 check_main.py 恢复后继续 | 无 | 0=完成；1=主界面恢复失败；2=上限 OCR 失败 |
| `scripts/gather_res.py` | 采集一种资源：进采集界面后先检测右下"自动"按钮是否旋转（连续帧差分），未开启自动采集则先点击开启，再按剩余百分比自动定时长：>70% 采 1 分钟、40%-70% 采 3 分钟、<40% 采 5 分钟（OCR 失败默认 3 分钟）；完成后自动回主界面并复检（3 次重试），随后自动复查全部资源剩余（同 check_res，附在 RESULT 行）；`--no-recheck` 跳过复查（多资源连续采集时用，分组编排规则见母 SKILL.md 典型编排） | 资源名或序号 1-7：鱼/塑料/木材/碎布/废金属/玻璃/海藻；可选 `--no-recheck` | 0=采集完成（RESULT 含时长与全资源剩余）；1=参数错误/主界面恢复失败/退出失败 |
| `scripts/force_main.py` | 强制回主界面（check_main 失败时用）：重启游戏→轮询等加载（上限 60 秒）→超时再跑一次 check_main 兜底 | 无 | 0=已在/已回主界面；1=强制恢复失败 |
| `scripts/battle_run.py` | 自动闯关长跑（**必须后台启动**）：开战 12 秒后跳过看结果，胜→直接下一关，败→再战；连续 5 败或单场超 15 分钟告警退出（告警只打印 [ALERT] 行，不弹窗，由 agent 转告用户）；**任何退出路径（告警/中断/异常）结束后先自动回主界面、再经 game_lib.push_result 自动推送战果**（日间直推微信、夜间写夜间日志；`--stop` 强杀不走自推，由停止方推送），末尾输出 RESULT 行；启动写 PID 与 `fkssj_battle_done.pending` 兜底标记，`--stop` 按 PID 停止后台闯关 | 可选 `--stop` | 0=结束且回主界面成功 / 未在运行时停止成功；1=异常、回主界面失败或停止失败 |
| `scripts/claim_online_reward.py` | 手动单次领取城战在线奖励：主界面 →"城战/世界"→"在线奖励"，点第 x 次领取按钮后回主界面（点击完成即视为领取成功，奖励到账以游戏内实际为准） | 领取次数 1-7 | 0=第 x 次领取成功且回主界面；1=参数错误/不在主界面/进界面失败/回主界面失败 |

已知坑：

- **RESULT 行不一定在最后一行**：个别路径（如 check_ships 部分成功）RESULT 在
  返回主界面之后打印，exit code 才是权威。
- **Git Bash 里用 `/c/...` 路径调 python 会失败**：原生 python.exe 不做 MSYS
  路径转换，`python /c/Users/.../check_main.py` 会报
  `can't open file 'C:\c\Users\...'`（no such file)。一律用正斜杠原生路径，例如：

```text
<PYTHON> <SKILL_DIR>/scripts/check_main.py
```

- **后台长跑勿用 nohup/disown/setsid 启动**：Hermes 终端会直接拒绝 shell 级后台
  包装（命令根本不执行）；一律用 PowerShell 分离启动器，模板见
  `references/battle.md`（battle_run/claim_seq）与 `references/chat.md`（chat_watch）。
