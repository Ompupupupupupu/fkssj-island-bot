# 故障排查

> **职责**：运行本 skill 脚本时的常见现象、原因与处理。
> **何时读取**：遇到报错、异常现象（连接失败、exit 2、主界面误判），或不确定
> 后台长跑是否在跑时。

| 现象 | 原因 | 处理 |
|---|---|---|
| `ConnectionRefusedError` / `no devices` | 模拟器未启动 | 先启动雷电模拟器，再跑 `start_game.py` |
| setup_emulator exit 2 | 配置修正需重启模拟器才生效 | 重启后重跑 setup_emulator 验证；仍不符则关闭模拟器再跑本脚本修正后启动 |
| start_game 超时后自动恢复成功 | 游戏启动后有弹窗遮挡 | 属预期兜底路径，无需处理 |
| check_main 反复 NOT_MAIN（兜底按钮也无效） | 模态弹窗遮挡（如联盟成员列表） | `force_main.py` 重启游戏兜底 |
| check_main 与 force_main 双双 NOT_MAIN，重启游戏后弹窗原样复现 | 模态弹窗「重要消息：您的账号在其他设备登录」+「重启游戏」按钮，属账号级冲突，重启游戏无法消除 | 不要点击（点了也会再次弹出）；如实上报用户，需用户在另一台设备退出游戏或改在本机登录后再跑脚本 |
| check_ships exit 2 | 船货物不足，交货被"所需产品不足"弹窗拒收（脚本已自动点弹窗退出键回贸易页） | 告知用户补货后重跑，属预期行为 |
| check_ships exit 1（未知/交货后未知） | 船状态读色不匹配任何参考色（界面被弹窗/动画遮挡或界面变化） | 重跑一次；复现则截屏按 maintenance.md 校准流程核对船点颜色 |
| check_res exit 2 | 上限 OCR 失败 | 重跑一次；仍失败检查 CAP_BOX 裁剪框 |
| 主界面误判 | 游戏昼夜光照导致像素色漂移 | 容差 COLOR_TOL 已设 10，勿调大 |
| 不确定闯关/领取序列/私聊监视是否在跑 | 后台长跑与常驻监视无窗口 | 查 `$TEMP` 下 `fkssj_battle.pid` / `fkssj_claim_seq.pid` / `fkssj_chat_watch.pid`，存在即在跑 |
| 定时任务触发时闯关在后台跑 | 长跑与其他任务抢设备 | 其他任务优先，处理流程见 `references/battle.md` |
| 定时任务询问"是否启动游戏" | 游戏未运行，prompt 已内置询问规则 | 同意则自动启动模拟器+游戏后继续；不同意/3 分钟未回复自动跳过本轮 |
| 后台启动器 `powershell -File launch_*.ps1` 退出码 0、终端无输出、PID 文件不出现、长跑日志时间戳没更新（还是上一轮内容） | 启动器 .ps1 含非 ASCII 字节（中文注释）：PS 5.1 按 ANSI/GBK 解析无 BOM 文件，整段 `Start-Process` 不执行 | 把启动器改为纯 ASCII（注释用英文）；`grep -nP '[^\x00-\x7F]' <启动器>` 返回 1 为干净，详见 `references/battle.md` |
| 整点没收到货轮/商船提醒，或私聊有红点但没提醒 | 计划任务未注册/被误删，或 chat_watch 未启动、本轮在让位 | 排查步骤见 `references/chat.md` 排查节 |
| 长跑结束没收到战果推送 | 夜间战果已记入夜间日志（待 08:04 统一推送）；或日间 3 次直推尝试全败、标记保留待兜底；或已被停止/让位流程推送并删除标记 | 夜间属预期，等 08:04 夜间总结推送；日间查 `$TEMP` 对应 `*_done.pending` 仍在则待顺路兜底，失败原因看 `$TEMP/fkssj_push.log`（每次尝试一行），或直接让我取日志尾部战果 |
| 一整轮检查过去微信毫无动静 | 正常轮静默（v3.2.3 起日间一切正常不汇报）或夜间窗口；静默实现 = 会话最终响应输出 `[SILENT]` 标记（Hermes cron 原生机制，平台据此跳过投递）；若桌面端会话里也没有本轮记录则是任务未触发 | 设计内行为无需处理；每轮结果可看桌面端会话，计数见次日 01:04 每日服务总结（`$TEMP/fkssj_stats.log`）；偶发单条消息漏进微信 = 该轮 LLM 把标记写成了变体（2026-10-19 05:35 一次：输出中文 `[静默]` 而非 `[SILENT]`，平台只认字面标记、不识别即照投），模板已写明"逐字输出英文 [SILENT]、勿写成 [静默] 等变体"，复发再看 |
| 微信没收到某轮定时任务结果，桌面端会话里却有（2026-10-18 实证，两种相反场景同症异因） | ① **聊天中**：iLink 微信通道 30 秒全局冷却被所有出站共享（对话回复、cron 投递、脚本推送同抢一条），投递/直推撞上对话回复的冷却即失败且 cron 投递**不重试**（`rate limited`；2026-10-18 上午聊天窗 09/10/11 点货轮失败即此型）；② **长时间不聊**：context_token 陈旧（最后入站一段时间后失效，精确时长未测出；2026-10-18 单次观测 13:18 入站、15:00 货轮仍 ok、15:01 起全灭）时主动推送返回 prepare failed，适配器去 token **立即**重发 → 距第一发不足 30 秒自撞冷却 → 每次调用内部互撞、**连续 100% 失败**且日志同样显示 `rate limited`（2026-10-18 15:01–18:42 连续 18 轮投递+3 次货轮全灭即此型，18:52 用户一条入站后 19:00/19:05 投递立即恢复） | 会话本身已正常执行：结果看桌面端会话或 `$TEMP/fkssj_stats.log`；① 建议向 Hermes 反馈"cron 投递失败时按 30 秒冷却做重试"；② 恢复法 = 给 bot 发一条消息刷新 context_token（长时间没收到任何主动推送时，先发一条再观察）；货轮 40 秒重试仅对①有效、对②无效（每次调用内部自撞，重试同样失败） |
| 暂停期间仍有 fkssj 定时任务触发 | 暂停只删除暂停时刻已存在的任务，暂停后用户又新建的任务不受影响；或暂停协议第 7 步漏删 | `/cron list` 按【fkssj …】标识核对：残留的暂停前任务手动删除，暂停后新建的属合理保留 |
| 说"暂停自动化"满 1 小时没收到询问，或"恢复自动化"后任务没回来 | 暂停时无任何自动化在开（不建询问任务，属正常）；询问任务已触发过一次（repeat=1 一次性，跑完系统自动收尾）；`$TEMP/fkssj_pause_state` 被外部删除（视为已恢复）；询问会话的微信投递撞上 iLink 30 秒冷却（见上一行）；或 Hermes /cron 未运行（cron 会话不触发） | 排查步骤见 `references/pause.md` 排查节 |
